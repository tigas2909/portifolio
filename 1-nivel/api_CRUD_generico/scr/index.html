API Genérica

Ferramenta simples para testes rápidos, prototipação e operações CRUD em bancos de dados que seguem o padrão definido nesta documentação.

1. Sobre a API

Esta API foi criada para facilitar testes rápidos em bancos de dados que seguem uma estrutura padronizada.

A ideia é permitir que uma nova tabela possa ser utilizada pela API sem a necessidade de criar um Controller e um Repository específicos para cada entidade.

⚠️ Atenção: esta API foi desenvolvida para testes rápidos, protótipos, projetos pessoais e pequenas aplicações.
⚠️ Não recomendada para projetos empresariais de grande porte: esta API não foi projetada para sistemas corporativos, aplicações de grande escala ou APIs públicas que necessitem de recursos avançados de segurança, autenticação, autorização, auditoria, controle de permissões, rate limiting, versionamento e regras de negócio complexas.

Para projetos grandes ou sistemas empresariais, recomenda-se desenvolver uma arquitetura específica para o projeto, implementando as regras de negócio e os mecanismos de segurança necessários.

2. Funcionamento

A API possui uma arquitetura simples dividida em algumas camadas: 

Request
   ↓
Router
   ↓
Controller
   ↓
Repository
   ↓
PDO
   ↓
MySQL

Router

Responsável por identificar o método HTTP e os parâmetros enviados pela URL.

Controller

Responsável por receber a requisição e chamar as operações necessárias do Repository.

Repository

Responsável pelas operações diretamente relacionadas ao banco de dados.

PDO

Responsável pela comunicação entre a aplicação PHP e o banco de dados.

3. Requisitos do banco de dados

Para que a API funcione corretamente, as tabelas precisam seguir algumas convenções.

Importante: essas convenções são obrigatórias para esta versão da API. Tabelas que não seguirem o padrão podem causar erros durante determinadas operações.

3.1 Prefixo das tabelas

Todas as tabelas utilizadas pela API devem possuir o prefixo tb_. 

tb_teste
tb_produto
tb_cliente
tb_usuario

Ao enviar: 

"table": "produto"

a API automaticamente utilizará: 

tb_produto

3.2 Chave primária

A chave primária deve seguir o formato: 

id_nomeDaTabela

Por exemplo:

tb_produto
    ↓
id_produto

3.3 Status

Para utilizar as operações de registros ativos, inativos e o delete lógico, a tabela deve possuir uma coluna chamada status.

Os valores utilizados pela API são: 

ativo
inativo

Exemplo:

status ENUM('ativo', 'inativo') DEFAULT 'ativo'

3.4 Exemplo completo

CREATE TABLE tb_teste (
    id_teste INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    valor DECIMAL(10,2),
    status ENUM('ativo', 'inativo') DEFAULT 'ativo'
);
Seguindo esse padrão, a tabela poderá utilizar as operações genéricas da API.

4. Conexão com o banco

As informações de conexão são enviadas através do objeto connection. 

{
    "connection": {
        "dsn": "mysql:host=localhost;dbname=api;charset=utf8mb4",
        "username": "usuario",
        "password": "senha"
    }
}

5. Estrutura da requisição

As requisições utilizam dois objetos principais:

  • connection — informações do banco;
  • info — informações da operação.
{
    "connection": {
        "dsn": "...",
        "username": "...",
        "password": "..."
    },

    "info": {
        "table": "teste"
    }
}

6. GET

GET Buscar todos os registros 

GET /index.php

Body:

{
    "connection": {
        "dsn": "mysql:host=localhost;dbname=api;charset=utf8mb4",
        "username": "usuario",
        "password": "senha"
    },

    "info": {
        "table": "teste"
    }
}

GET Buscar por ID 

GET /index.php?id=10

Busca um registro específico utilizando a chave primária correspondente à tabela.

GET Buscar registros ativos 

GET /index.php?acao=selectAtivo

Retorna somente registros cujo campo status seja ativo.

GET Buscar registros inativos 

GET /index.php?acao=selectInativo

Retorna somente registros cujo campo status seja inativo.

7. POST

POST Inserir registro 

POST /index.php

Exemplo:

{
    "connection": {
        "dsn": "mysql:host=localhost;dbname=api;charset=utf8mb4",
        "username": "usuario",
        "password": "senha"
    },

    "info": {
        "table": "teste",
        "nome": "teste1",
        "valor": 2.20,
        "status": "ativo"
    }
}

A API utiliza automaticamente os campos enviados para montar a instrução de inserção.

O campo da chave primária não precisa ser enviado quando ele estiver configurado como AUTO_INCREMENT.

8. PUT

PUT Atualizar registro 

PUT /index.php?id=10&acao=atualizar

Exemplo:

{
    "connection": {
        "dsn": "mysql:host=localhost;dbname=api;charset=utf8mb4",
        "username": "usuario",
        "password": "senha"
    },

    "info": {
        "table": "teste",
        "nome": "Novo nome",
        "valor": 5.50
    }
}

O registro identificado pelo ID será atualizado com os campos enviados no objeto info.

PUT Delete lógico 

PUT /index.php?id=10&acao=delete

A API não remove fisicamente o registro do banco.

Em vez disso, altera o campo status para inativo.

Importante: o registro continua armazenado no banco de dados. Ele apenas passa a ser considerado inativo.

9. Parâmetros da URL

Parâmetro Exemplo Função
id ?id=10 Identifica um registro específico.
acao ?acao=selectAtivo Define uma operação específica.

10. Códigos HTTP

Código Nome Utilização
200 OK Operação realizada com sucesso.
201 Created Registro criado com sucesso.
400 Bad Request Requisição inválida.
404 Not Found Registro não encontrado.
405 Method Not Allowed Método HTTP não permitido.
500 Internal Server Error Erro interno da aplicação.

11. Resumo dos endpoints

Método URL Operação
GET /index.php Buscar todos
GET /index.php?id=10 Buscar por ID
GET /index.php?acao=selectAtivo Buscar ativos
GET /index.php?acao=selectInativo Buscar inativos
POST /index.php Inserir registro
PUT /index.php?id=10&acao=atualizar Atualizar registro
PUT /index.php?id=10&acao=delete Inativar registro

12. Exemplo completo

Exemplo de uma tabela compatível: 

CREATE TABLE tb_produto (
    id_produto INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    valor DECIMAL(10,2),
    status ENUM('ativo', 'inativo') DEFAULT 'ativo'
);

Inserção:

POST /index.php

{
    "connection": {
        "dsn": "mysql:host=localhost;dbname=api;charset=utf8mb4",
        "username": "usuario",
        "password": "senha"
    },

    "info": {
        "table": "produto",
        "nome": "Teclado",
        "valor": 150.00,
        "status": "ativo"
    }
}

Consulta:

GET /index.php

Consulta por ID:

GET /index.php?id=1

Inativação:

PUT /index.php?id=1&acao=delete

13. Considerações

Esta API prioriza simplicidade e velocidade de implementação.

Seu principal objetivo é permitir que um banco de dados padronizado possa ser testado rapidamente através de requisições HTTP, sem a necessidade de implementar uma estrutura completa para cada entidade.

Objetivo principal: testar rapidamente um banco de dados seguindo o padrão definido nesta documentação.
Não confundir com uma API de produção: para sistemas reais de grande porte, a arquitetura deve ser adaptada às necessidades específicas do projeto.
